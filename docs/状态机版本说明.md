# 力控状态机版本

分支：`refactor/control-state-machine`。基于原分支提交 `662a04b` 和本次改造前的本地 `ControlLoop.cpp`。

## 从哪里读

1. `include/ControlConfig.h`：所有新增框架参数，以及原有导纳质量、阻尼、刚度、速度、滤波、死区、关节限位。
2. `src/ControlLoop.cpp`：周期等待、读取开关、调用状态机、更新显示。
3. `src/ControlStateMachine.cpp`：`update()` 是入口；`advanceStart()` 是启动；`advanceStop()` 是停机。
4. `src/ControlCycle.cpp`：读取实际位姿、滤波、导纳、模式对应的目标计算、限位、发送。
5. `src/NrcControlHardware.cpp`：全部运行期厂家接口，以及原始传感器数据适配。
6. `include/SensorCalibration.h`：非阻塞清零采样。
7. `tests/ControlStateMachineTests.cpp`：模拟硬件和离线流程测试。

`ControlHardware` 是硬件接口，状态机和导纳计算不包含厂家头文件。离线测试通过模拟接口驱动同一份生产状态机和导纳代码，不会连接机器人。

## 状态和执行线程

```text
关闭 ──观察到关闭后重新开启──> 启动 ──完成──> 位置力控 <──同步实际位置──> 末端旋转力控
 ↑                             │              │                         │
 └────停机完成────────────── 停机 <────关闭请求、运行中清零或故障────────────┘
                              │
                              ├─故障触发且清理完成──> 故障，允许关闭再开启重试
                              └─清理失败──────────> 故障，禁止开关重试
```

另有单独的“清零”状态。运行中清零会先完成停机，清零完成后留在关闭状态，必须重新开关力控，不自动恢复运动。

一个主控制线程负责运行期全部厂家调用。原传感器显示线程移除，大小量程原始显示值仍写入变量7～18，每500毫秒更新一帧，每个控制周期最多写一个变量。日志仍使用原异步日志线程。

## 启动和停止顺序

启动：检查未使能且停止 → 清错 → 分步清零 → 设置伺服准备 → 上使能 → 开启关节跟踪 → 等待伺服状态3 → 读取实际位姿并清零导纳状态 → 运行。

保留实际仓库中的 `PowerOn → RKG_Open → 等待状态3` 顺序。原未提交注释写“使能之前”，与实际调用位置不一致，本版以实际执行顺序为准。启动动作现在分布在不同周期，调用间隔和固件状态窗口仍需实机验证。

停机：立即禁止新的导纳目标 → 调用 `NRC_RKG_Stop()` → 检查运动状态0且四轴位置连续稳定100毫秒 → 调用 `NRC_PowerOff()` → 明确读到状态0或1 → 完成。

本版保留仓库当前停机顺序。先前讨论的“只停发目标、下使能后才关闭跟踪”没有直接采用：现有头文件没有保证停发目标会停止追赶最后一个目标。`NRC_RKG_Stop()` 的头文件说明为立即停止轨迹生成，`NRC_PowerOff()` 明确要求不在运动中调用。如果特定固件确实要求断使能后才能关闭跟踪，需要先确认厂家提供的受控减速接口及其完成条件，再调整 `advanceStop()`。

关闭跟踪或下使能失败会记录返回码；关闭跟踪失败还会记录实际伺服状态。停机未确认完成会进入锁定故障，不再输出“伺服保持使能”或“已安全停止”等未经状态验证的结论。需要人工检查后重启程序，不会循环重复下电。

伺服状态2为报警，不当作下使能成功。关闭跟踪返回失败时，即使伺服看起来已断开，也不自动忽略该失败。

## 模式切换

- 两个方向切换都读取真机实际位姿，把当前位置作为新的局部原点，清空导纳位置增量、速度和滤波历史。
- 同步当拍不发送新目标，下一拍从零偏移开始。这样不再把旧的累计虚拟位置带入新模式。
- 位置模式只使用平移力，使用原工具系投影及完整逆解。
- 旋转模式只使用末端力矩，固定进入旋转模式时的前三个关节，第四关节目标为实际起始角度加导纳角增量；不调用逆解。
- 大小量程切换同样重新同步真机状态。小量程的方向仍沿用原代码，只反转第一项平移力。

这避免继承旧目标，但不能消除控制器已经缓存的轨迹；真实跟踪延迟、机械惯量和切换瞬态仍须低速验证。

## 时间、清零和退出

- 运行、启动、停机、清零请求周期为1毫秒；关闭和故障状态为10毫秒，原程序关闭时为200毫秒。
- 导纳积分仍为固定1毫秒，未改变公式及调参含义。严重周期延迟超过 `MAX_CONTROL_GAP_MS`（默认10毫秒）触发故障停机，不进行补发追赶。小幅抖动仍会造成实际时间与积分时间偏差。
- 清零先等待10毫秒，再每2毫秒采一帧，共50帧。迟到不会重复补采；取消、超时或无效数据保留上一次有效零点。
- 状态机使用的零点由 `NrcControlHardware` 管理；`RobotUtils` 中旧的阻塞式 `zero_force_sensor()` 保留供旧代码参考，新主循环不调用它。
- `SIGINT` 和 `SIGTERM` 只置退出标志，循环继续推进停机。正常退出返回0；存在故障或停机未完成返回1。
- 阻塞等待被拆分不代表厂家调用本身不阻塞。初始化阶段的 `SystemStartup()` 仍沿用原实现，实时调度权限、日志锁、厂家调用耗时也仍是现有运行条件。

## 如何编译和看流程

在与控制器匹配的原有 Ubuntu 编译环境中执行：

```bash
make CXX=g++-4.8
```

Makefile 自动收集 `src/*.cpp`，新增头文件变化也会触发重编译。本版没有更换控制器的32位库或运行库。此电脑为 Windows，尚未验证 Linux 控制器的完整链接和运行库兼容性。

离线测试可以使用普通编译器，不需要厂家库：

```bash
make test TEST_CXX=g++
./state_machine_tests --demo
```

Windows PowerShell 有 `g++` 时：

```powershell
g++ -std=c++11 -Wall -Wextra -pedantic -I./include src/Admittance.cpp src/ControlCycle.cpp src/ControlStateMachine.cpp tests/ControlStateMachineTests.cpp -o state_machine_tests.exe
.\state_machine_tests.exe
.\state_machine_tests.exe --demo
```

`--demo` 输出开启、位置模式、旋转模式、切回位置和停机日志；可在 `ControlStateMachine::update()` 设置断点，用同一个测试程序单步调试。

## 已验证与未验证

已在 Windows 的本地编译器以 C++11 编译并运行11组离线测试，覆盖正常启停、全部启动步骤取消、启动接口失败和超时、两向模式及传感器切换、清零采样和中断、运行期故障、连续停稳窗口、清理失败锁定和退出。核心代码使用严格警告编译通过；厂家适配层与周期循环通过使用真实项目头文件的语法检查。

离线测试模拟的是接口结果和状态变化，不模拟电机动力学，也不证明真机在1毫秒内完成所有调用。Linux 主程序完整编译还需原 Ubuntu 环境（Windows 缺少原代码的 `sys/mman.h` 和 `localtime_r`）。厂家函数无法从接口返回可靠传感器时间戳，陈旧数据检测和控制器级通信看门狗未在此次重构中实现。
